# Changelog

Формат по [Keep a Changelog](https://keepachangelog.com/ru/1.0.0/), версии — по [Semantic Versioning](https://semver.org/lang/ru/).

Текущую версию показывает команда `/version`, она же логируется при старте бота и берётся из `package.json`.

PATCH-версия (`X.Y.Z`, `Z > 0`) — багфикс, MINOR/MAJOR (`X.Y.0`) — релиз. В канал `#обновления` автоматически публикуются только релизы; патчи остаются только здесь и в `/changelog`.

## [Unreleased]

## [3.8.0] — временные комнаты переехали в отдельную категорию

### Исправлено

- Временные голосовые комнаты участников создавались в той же категории, что триггер-канал и панель управления («Временные комнаты»), — со временем она зарастала десятками комнат. Теперь для самих комнат `scripts/setup-temp-voice.js` создаёт отдельную категорию «Активные комнаты» (`roomsCategoryId`); если она ещё не настроена (старый деплой) — используется прежняя категория как запасной вариант, а не создание без родителя вообще.

## [3.6.0] — релиз в канал только для настоящих релизов, не для патчей

### Добавлено

- Автопост "что нового" в `#обновления` теперь пропускает патч-версии (`X.Y.Z`, `Z > 0`) — публикуется только когда версия вида `X.Y.0` (релиз). Раньше публиковался любой бамп версии, включая мелкие багфиксы.

### Исправлено

- `parseChangelog` не находил ни одной секции, если `CHANGELOG.md` содержал CRLF-переводы строк (`$` в регулярке не матчился перед висящим `\r`) — `/changelog` и автопост молча переставали работать без единой ошибки. Сейчас в репозитории только LF, поэтому продакшена это не касалось, но парсинг теперь устойчив к обоим вариантам.

## [3.5.0] — темы тикетов: убраны донат и безопасность аккаунта

### Убрано

- Тема тикета «Донат / платежи» — вместе с ролью-специалистом `Payments` и шаблоном ответа «Нужны детали платежа».
- Тема тикета «Безопасность аккаунта» — вместе с ролью-специалистом `Security` и шаблоном ответа «Рекомендация по безопасности». Это была единственная тема с ускоренной эскалацией (`urgent`) — сейчас ни одна тема так не отмечена.

### Изменено

- Роль-специалист темы «Баг / техническая проблема» переименована из `Bugs` в «Разработчик бота» — баг в самом боте это вопрос того, кто его написал, а не общей поддержки.

## [3.4.0] — сообщения от имени бота

### Добавлено

- `/say <канал> <текст>` — отправить сообщение от имени бота в указанный канал (только Administrator).
- `/dm <пользователь> <текст>` — отправить личное сообщение от имени бота (только Administrator). Обе команды логируются в security-log (администратор, канал/получатель, текст) — Discord не пишет такие действия в свой audit log сам.

## [3.3.0] — стартовая роль сразу при верификации

### Изменено

- Роль уровня репутации «Новичок» теперь выдаётся сразу при прохождении верификации, а не только после первого полученного очка репутации.

## [3.2.0] — ручная настройка ролей верификации

### Добавлено

- `/verification-role verified|unverified <роль>` — администратор указывает роль напрямую через Discord role-picker, конфиг обновляется сразу, без редеплоя.

### Исправлено

- `scripts/setup-verification.js` больше не переопределяет уже настроенную (через команду выше или предыдущий запуск) роль поиском по имени — раньше повторный запуск при несовпадении имён создавал рядом второй, дублирующий "верифицирован"/"не верифицирован".

## [3.1.3] — верификация выдаёт свою роль, не Participant

### Исправлено

- Верификация выдавала роль `Participant` из `scripts/setup-roles.js` — роль общего назначения, никак не связанную по смыслу с "прошёл капчу", и путавшуюся с ролью `Верифицирован`, которую администратор мог создать вручную под тем же смыслом. `scripts/setup-verification.js` теперь находит/создаёт отдельную роль `Верифицирован` специально для этого. `Participant` убрана из `scripts/setup-roles.js` — больше не использовалась нигде и пересоздавалась при каждом деплое, даже если её удаляли вручную.

## [3.1.2] — исправлена проверка "уже верифицирован"

### Исправлено

- Кнопка "Пройти верификацию" определяла "уже верифицирован" по **отсутствию** роли "не верифицирован", а не по **наличию** роли "верифицирован" — это не одно и то же. Если у участника не было ни одной из двух ролей (например, админ вручную снял "верифицирован", не выдав обратно "не верифицирован"), бот ошибочно считал его верифицированным и отказывался показывать капчу, оставляя без роли "верифицирован" вообще. Тот же баг был бы у любого, кто зашёл на сервер до включения верификации.

## [3.1.1] — роль "Новичок" с первого очка репутации

### Исправлено

- Роль уровня репутации не выдавалась вообще, если у участника было меньше 5 очков — стартовый уровень "Новичок" не имел собственной роли, а первое полученное очко не двигает индекс уровня (0 и 1-4 очка — оба "Новичок"), поэтому проверка "уровень повысился?" не срабатывала. Теперь `scripts/setup-reputation.js` создаёт роль и для "Новичок", а `giveReputation()` явно отмечает первое полученное очко (`firstPoint`) — роль выдаётся сразу.

## [3.1.0] — репутация участников

### Добавлено

- Система репутации (`reputation/`): `/rep give` (+1 участнику, кулдаун 20ч на одного и того же человека, лимит 5 разным людям в сутки), `/rep profile` (уровень-титул от "Новичок" до "Икона сообщества" с текстовым прогресс-баром до следующего), `/rep leaderboard` (топ-10), `/rep set` (ручная правка для модерации). Повышение уровня выдаёт роль (создаётся автоматически, `scripts/setup-reputation.js`) и публикует карточку; раз в неделю бот сам постит топ-10 в канал `#рейтинг` с изменением позиции относительно прошлой недели.

## [3.0.0] — тикеты на тредах и Components V2, новые системы

### Добавлено

- Новые команды: `/ping`, `/help`, `/userinfo`, `/serverinfo` (общие), `/slowmode`, `/role add|remove` (модерация).
- `utils/loadCommands.js` теперь помечает каждую команду её категорией (папкой) — используется `/help` для группировки, не меняет контракт для `deploy-commands.js`/`index.js`.
- Anti-nuke: защита от вебхук-нюка — новый вебхук в канале проверяется через audit log, и если его создал не доверенный пользователь, вебхук удаляется автоматически (требует intent `GuildWebhooks`).
- Automod: детектор фишинговых/скам-ссылок (поддельные раздачи Nitro, скам-трейды Steam) и детектор избыточного капса.
- `/lockdown on|off` — ручная экстренная блокировка сервера (запрет писать/заходить в голосовые всем участникам), состояние переживает перезапуск бота.
- `/rules` и `scripts/setup-rules.js` — правила сервера, оформленные только официальной Markdown-разметкой Discord (`#`, `##`, `###`, subtext через `-# `), без эмодзи; скрипт публикует и закрепляет их в канале `#правила`, повторный запуск редактирует то же сообщение вместо дублирования.
- `/security-status` показывает активный lockdown и использует заголовки/списки Markdown для более читаемого вывода.
- Система тикетов поддержки переписана на приватные **треды** вместо отдельных каналов: панель с кнопкой на каждую тему обращения → модальная форма с описанием (для жалобы на игрока — выбор нарушителя через `UserSelectMenu`), приветственная подсказка и мини-чеклист для staff под тему сразу при создании, история жалоб на игрока за 30 дней в карточке тикета, кнопка "Наказать" (мут/бан) прямо из тикета с проверкой реальных прав исполнителя, ускоренная эскалация для темы "Безопасность аккаунта", DM-напоминание автору, если он сам долго не отвечает, антиспам-задержка перед повторным открытием тикета, 14 готовых ответов (`/ticket reply`), оценка поддержки после закрытия, `/ticket list|stats|reopen`, `/mytickets`.
- Панель поддержки, карточка тикета и все постоянные сообщения тикетов переведены на Discord **Components V2** (`Container`/`TextDisplay`/`Separator`) вместо embed'ов — без единого эмодзи, отдельная кнопка на каждую тему обращения, единый серый цвет всех кнопок.
- Временные голосовые комнаты (`voice/`): управление только через кнопки на панели — у владельца нет `Manage Channels` и нативного статуса голосового канала Discord, чтобы обойти кнопки было нельзя; категория для новой комнаты резолвится с подстраховкой через `fetch()`, если её не оказалось в кэше.
- Система предложений (`suggestions/`) — кнопка "Предложить идею" → модалка → публикация предложения в канал для обсуждения.
- `/status` (`presence/`) — фиксированный текст активности бота с шаблонами `{members}`/`{uptime}` либо ротация из нескольких вариантов по таймеру.
- `/dashboard` — сводная панель модератора: тикеты, статус security-модулей, предупреждения, временные комнаты.
- `/changelog` и автоматический анонс новой версии в канале `#обновления` при первом запуске бота на ней (`changelog/`, `scripts/setup-changelog.js`).

### Изменено

- `utils/embeds.js`: единый визуальный паттерн для всех embed'ов бота — заголовок как `### текст` и краткое описание под ним как `-# текст` (Discord subtext) вместо `EmbedBuilder#setTitle`. Применено ко всем сообщениям во всех фичах (moderation-команды, security-логи, tickets/voice/suggestions), поля (`addFields`) не тронуты.
- `deploy-commands.js`: регистрация slash-команд одновременно и глобально, и на конкретном сервере (`GUILD_ID`) заставляла Discord показывать каждую команду дважды — теперь при заданном `GUILD_ID` регистрация только на сервере (мгновенная), с явной очисткой глобальных команд.

### Исправлено

- "Обсудить голосом" в тикете теперь доступна только staff — раньше голосовой канал мог создать и сам автор тикета.

## [2.0.0] — инфраструктурный рефакторинг

### ⚠️ Важное изменение (breaking)

- Хранение конфигурации переведено с файлов `data/*.json` на **PostgreSQL**. Бот больше не запустится без рабочего `DATABASE_URL`. Для переноса существующих данных — `npm run db:migrate-json`.

### Добавлено

- `Dockerfile` и `docker-compose.yml` — контейнеризация бота вместе с PostgreSQL.
- eslint + prettier + CI на GitHub Actions (с сервисом PostgreSQL для тестов).
- Unit-тесты на встроенном `node:test` для чистой бизнес-логики.
- `README.md` с инструкциями по установке и настройке.
- `utils/pgStore.js` — атомарный read-modify-write через транзакцию с `SELECT ... FOR UPDATE` (защита от гонок даже при нескольких инстансах бота).
- Публичный API `security/index.js` (`getConfig`, `updateConfig`, `createBackup`, `listBackups`, `restoreBackup`, `VERIFY_BUTTON_ID`) — команды и скрипты настройки больше не обращаются к внутренним файлам `security/` напрямую.

### Изменено

- Устранена гонка read-modify-write в JSON-хранилище (была до перехода на PostgreSQL) — атомарная запись через отдельную очередь на файл.
- `tickets/tickets.js` и `voice/tempChannels.js` разделены на `model.js` (домен: правила, создание/закрытие тикета, действия над комнатой) и `handlers.js` (роутинг Discord-взаимодействий через карту `customId → функция` вместо цепочки `if/else`).
- `index.js`: graceful shutdown по `SIGINT`/`SIGTERM` (закрывает соединение с Discord и пул PostgreSQL).

- Система безопасности: anti-nuke, raid shield, audit log, automod, верификация новых участников, автобэкап структуры сервера.
- Система тикетов поддержки с выбором темы, взятием в работу и архивом переписки.
- Временные голосовые комнаты с полным набором действий владельца (лок, скрытие, лимит, кик, блок, передача владения).
- Команды модерации: `/ban`, `/kick`, `/timeout`, `/warn`, `/warnings`, `/clear`, `/unban`, `/backup`, `/security-status`.
