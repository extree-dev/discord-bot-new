# discord-bot

Discord-бот для модерации сервера на [discord.js](https://discord.js.org/) v14: система безопасности (антинюк, raid shield, automod, верификация), тикеты поддержки и временные голосовые комнаты.

## Возможности

Общее правило видимости: ответ на любую команду или нажатие кнопки — ephemeral (виден только тому, кто её вызвал/нажал), кроме единственного явного исключения — `/rep leaderboard` (топ репутации виден всем в канале, это витрина, а не личный ответ). Персистентные панели (открыть тикет, статус голосовой комнаты, предложить идею, ticket-log, карточка левел-апа/еженедельный топ репутации) — не ответы на команду, а самостоятельные публичные сообщения, их это правило не касается.

- **Общие** — `/ping`, `/help`, `/userinfo`, `/serverinfo`, `/rules`, `/version`, `/changelog`, `/mytickets`, `/rep` (репутация).
- **Модерация** — слэш-команды `/ban`, `/kick`, `/timeout`, `/warn`, `/warnings`, `/clear`, `/unban`, `/slowmode`, `/role`, `/lockdown`, `/ticket` (list/stats/reply/reopen/close), `/status` (управление статусом бота, с ротацией), `/dashboard` (сводная панель модератора), `/verification-role` (указать роли верификации напрямую, без редеплоя), `/say` (сообщение от имени бота в канал), `/dm` (личное сообщение от имени бота), `/dm-clear` (удалить сообщения бота в личке с участником), `/commands-channel` (ограничить общие команды одним каналом), `/temp-voice-category` (указать категорию для временных комнат), бэкап сервера, статус системы безопасности.
- **Безопасность** (`security/`)
    - **Anti-nuke** — следит за массовым удалением каналов/ролей, банами, выдачей опасных прав и созданием подозрительных вебхуков через audit log; при превышении лимита действий за окно времени снимает роли и банит исполнителя (если он не в списке доверенных).
    - **Raid shield** — при аномальном всплеске заходов новых участников временно поднимает уровень верификации сервера.
    - **Automod** — банит массовые упоминания, спам сообщениями, ссылки-приглашения, фишинговые/скам-ссылки, избыточный капс и запрещённые слова; копит предупреждения и эскалирует до таймаута/бана.
    - **Lockdown** (`/lockdown on|off`) — ручная экстренная блокировка всех каналов сервера, состояние сохраняется в БД.
    - **Верификация** — простая captcha (кнопка + модальное окно) перед выдачей роли на сервере.
    - **Audit log** — лог действий модерации в отдельный канал; туда же пишутся `/say` и `/dm` (кто из администраторов и что отправил от имени бота — Discord сам такое не логирует).
- **Кастомный мут** (`moderation/`) — `/timeout` и кнопка «Наказать → Мут» в тикетах-жалобах не используют нативный Discord-таймаут (Communication Disabled Until): у него жёсткое ограничение платформы — пока он активен, участник не может нажать вообще ни одну кнопку и использовать вообще ни одну слэш-команду на сервере, то есть не может даже подать апелляцию на само наказание. Вместо этого назначается роль `Muted` с явным запретом писать/реагировать/подключаться к голосу/использовать слэш-команды почти везде на сервере (оверрайт ставится на каждый канал и категорию, не только категории — иначе его мог перебить собственный оверрайт какого-то другого канала, `scripts/setup-roles.js`; на новые категории/каналы, созданные позже, оверрайт ставится автоматически). Кнопки при этом остаются доступны (Discord не считает их application-командами) — участник может открыть тикет апелляции с общей панели, писать в своём же треде (для тредов тикетов это отдельно возвращено явным allow-оверрайтом — категорийный запрет иначе заблокировал бы и это, `scripts/setup-tickets.js`) и подключиться к голосовому каналу, который staff создаст под его тикет (там уже есть персональный allow-оверрайт, он всегда сильнее ролевого запрета). Срок мута отслеживается отдельно (БД, не нативный Discord-таймер) и снимается автоматически по истечении либо кнопкой «Снять наказание» в тикете обжалования. `/dashboard` показывает число активных мутов.
- **Тикеты поддержки** (`tickets/`) — панель на Discord Components V2 (Container/TextDisplay, не embed): текстовый список тем обращения + сетка кнопок под ним, все кнопки одного серого цвета; клик по теме сразу открывает модальную форму с описанием проблемы (и доп. полем для некоторых тем; для жалобы на игрока — выбор через UserSelectMenu вместо ручного ввода ID), без промежуточного выпадающего списка. Тикет — приватный **тред**, а не отдельный канал (не расходует лимит каналов сервера, легко архивируется/переоткрывается). Приветственная подсказка и мини-чеклист для staff под конкретную тему сразу при создании; жалоба на игрока показывает историю его прошлых жалоб за 30 дней и даёт замутить/забанить прямо кнопкой из тикета — мут (кастомный, см. «Кастомный мут» выше) доступен любому staff тикета (включая Support/Beta-Support, у которых по дизайну нет личного права `ModerateMembers` — мутит от своего имени бот), бан по-прежнему только тем, у кого есть личное право `BanMembers`. Тикеты обжалования — с кнопкой «Снять наказание», сразу снимающей мут с автора тикета, без ручного `/timeout`. Служебные подтверждения действий (наказание/снятие наказания, закрытие тикета) — эфемерны нажавшему, если тикет закрывает сам автор, и видны всему треду, если закрывает staff (иначе автор бы их не увидел); готовые ответы (`/ticket reply`, «Быстрый ответ») по-прежнему видны всем. При любом закрытии (кем угодно, включая автозакрытие по неактивности) в тред падает отдельная видимая карточка с просьбой оценить работу поддержки (кнопки 1-5) — не в личные сообщения (бот их больше не шлёт сам, см. ниже), оценить может только автор тикета. Взятие в работу (и отпустить/переназначить другому staff кнопками, если исполнитель сменился), добавление участников (только staff создаёт и голосовую комнату для обсуждения — не автор), закрытие с HTML-транскриптом переписки в лог (открывается в браузере, оформлен под тёмную тему Discord — не плоский `.txt`), внутренние заметки staff (отдельный приватный тред), готовые ответы — командой `/ticket reply` или прямо кнопкой «Быстрый ответ» в тикете (14 шаблонов), приоритет — кнопкой «Приоритет» в любой момент переключает как staff, так и автор тикета (не только у заранее отмеченных тем): виден отдельной строкой в самой карточке тикета (сразу перерисовывается при переключении, не эмодзи-маркером в имени треда — по фидбэку администратора неудобно), приоритетные тикеты идут первыми в `/ticket list` и эскалируются быстрее. Статус (открыт/ждём автора/решён) — только текстом, тоже в карточке (не в имени треда — там только номер, тема и ник автора). Автоэскалация непринятых, автозакрытие неактивных тикетов, антиспам-задержка перед повторным открытием тикета, статистика (`/ticket stats` — включая среднее время первого ответа staff, `/ticket list`, `/mytickets`). Основная панель — апелляции наказаний, жалобы на игроков, общие вопросы, остальное; темы отмеченные `standalone` (сейчас — только "Баг") на неё не попадают, у них своя отдельная панель/канал/специалист-роль (см. ниже). **Испытательный срок для staff** — роли `Beta-Moderator`/`Beta-Support` (`scripts/setup-roles.js`/`scripts/setup-tickets.js`) видят и ведут тикеты как обычный staff, но закрыть тикет сразу не могут: запрос на закрытие уходит карточкой с кнопками «Подтвердить»/«Отклонить» в отдельный канал `#подтверждение-стажёров`, который видит только старший состав (Support/Moderator/Admin). Подтверждение закрывает тикет как обычно (с пометкой, кто подтвердил, в логе), отклонение просит указать причину и возвращает тикет в работу — на автора тикета и на закрытие им собственного тикета гейт не распространяется.
- **Баг-репорты** (`tickets/`, тема "bug" — standalone) — та же система, что тикеты (claim/close/notes/шаблоны/`/ticket stats`), но полностью отдельная очередь: своя панель в канале `#сообщить-о-баге` (не показывается на основной панели поддержки), тред открывается в этом же канале, автопинг только роли «Разработчик бота» — Support не дёргается вообще, это и была цель разделения. Роль «Разработчик бота» (существовавшая и раньше как специалист-роль для пинга) теперь ещё и полноправный staff для тикетов именно этой темы — сама берёт баг-репорт в работу и закрывает его, без Support/Moderator.
- **Временные голосовые комнаты** (`voice/`) — авто-создание личной комнаты при входе в триггер-канал (с подстраховкой на случай, если категория ещё не в кэше бота) в отдельной категории (по умолчанию «Активные комнаты», либо любая другая через `/temp-voice-category set`) — не там, где сам триггер-канал и панель управления, чтобы та не зарастала комнатами участников, управление (лок/скрытие, лимит, кик, блок, передача владения) только через кнопки на панели — у владельца нет `Manage Channels` и нативного статуса голосового канала Discord, чтобы обойти кнопки и поменять что-то напрямую было нельзя.
- **Предложения** (`suggestions/`) — кнопка "Предложить идею" в отдельном канале → модальная форма (заголовок + описание) → публикация в канал предложений для обсуждения командой и участниками.
- **Статус бота** (`presence/`) — `/status` задаёт фиксированный текст активности (Играет в/Смотрит/Слушает/Участвует в) с подстановкой `{members}`/`{uptime}`, либо ротацию из нескольких вариантов по таймеру.
- **Что нового** (`changelog/`) — `/changelog` показывает последние версии из `CHANGELOG.md` (все, включая патчи); при первом запуске бота на новой версии карточка с изменениями публикуется автоматически в канал `#обновления`, но только для релизов — версий вида `X.Y.0` (см. SemVer в `CHANGELOG.md`). Патч-версии (`X.Y.Z`, `Z > 0`) — багфиксы, они молча остаются только в истории.
- **Канал команд** (`commandsChannel/`) — `/commands-channel set|clear` ограничивает общие команды (не модерацию) одним каналом: вызов не в нём не выполняется, в ответ приходит ephemeral-подсказка (видно только автору) с указанием нужного канала.
- **Репутация** (`reputation/`) — `/rep give` даёт +1 репутации участнику (кулдаун 20ч на одного и того же человека, лимит 5 разным людям в сутки), `/rep profile` целиком одной картинкой (не embed/текстом) — баннер профиля пользователя как фон (градиент в цвет уровня, если баннера нет), круглый аватар в рамке цвета уровня, имя, уровень (титул от "Новичок" до "Икона сообщества"), полоса прогресса до следующего уровня того же цвета, строка "осталось N очков"/сколько репутации сам выдал, место в рейтинге (золото/серебро/бронза для топ-3) и уголок с иконкой/именем сервера; рисуется на сервере через `@napi-rs/canvas` (кириллица — через `@openfonts/noto-sans_cyrillic`, без системных шрифтов в контейнере). Цвет уровня — общий для роли и карточки: единственный источник — `LEVELS` в `reputation/model.js`. `/rep leaderboard` — тоже картинкой, не embed'ом, тем же визуальным языком, что и `/rep profile`: все места — одинаковые строки (аватар в рамке цвета уровня, уровень, сколько репутации сам выдал, полоса прогресса до следующего уровня тем же цветом, счёт), топ-3 отмечены только цветом номера места — без подиума/спецэффектов; `/rep set` — ручная правка для модерации. Роль уровня (включая стартовую "Новичок" — выдаётся сразу при верификации) выдаётся автоматически (роли создаёт `scripts/setup-reputation.js`) и публикует карточку при получении/повышении; раз в неделю бот сам постит ту же картинку топа с изменением позиции относительно прошлой недели (`+N`/`-N`/`=`/`новый` — цветная плашка у каждой строки) в канал `#рейтинг`. Обе картинки репутации (профиль и топ) делят общие примитивы рисования в `reputation/canvasUtils.js`.

## Требования

- Node.js 18+
- Discord-приложение и бот-токен ([Discord Developer Portal](https://discord.com/developers/applications))

### Права бота и intents

При приглашении бота на сервер нужны минимум права: `Manage Roles`, `Manage Channels`, `Kick Members`, `Ban Members`, `Moderate Members`, `Manage Messages`, `View Audit Log`, `Send Messages`, `Read Message History`, `Connect`/`Move Members` (для временных голосовых комнат), `Create Private Threads`/`Manage Threads` (для тикетов-тредов).

В Developer Portal → Bot включите privileged intents: **Server Members Intent** и **Message Content Intent** (используются `GatewayIntentBits.GuildMembers` и `GatewayIntentBits.MessageContent` в `index.js`).

## Установка

```bash
npm install
cp .env.example .env
```

Заполните `.env`:

| Переменная      | Обязательна | Описание                                                                                                                                              |
| --------------- | ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `DISCORD_TOKEN` | да          | Токен бота из Developer Portal.                                                                                                                       |
| `CLIENT_ID`     | да          | Application ID бота (для регистрации слэш-команд).                                                                                                    |
| `GUILD_ID`      | нет         | ID сервера для мгновенной регистрации команд на конкретном сервере (без него — глобальная регистрация, до часа на распространение).                   |
| `TRUSTED_IDS`   | нет         | ID пользователей через запятую, которым система безопасности всегда доверяет (не считает подозрительными). Владелец сервера доверенный автоматически. |

`.env` и всё содержимое `data/` (конфиги, счётчики тикетов, бэкапы) в `.gitignore` — не коммитятся.

## Запуск

```bash
npm run deploy   # зарегистрировать/обновить слэш-команды в Discord
npm start         # запустить бота
```

`npm run deploy` регистрирует команды на конкретном сервере, если задан `GUILD_ID` (и очищает глобальные — иначе одна и та же команда была бы видна дважды), иначе — глобально (до часа на распространение).

## Настройка после первого запуска

Все скрипты в `scripts/` (кроме `migrate-json-to-postgres.js`) идемпотентны: находят уже созданные роли/каналы/панели по сохранённому ID (запасной вариант — по названию, только если ID ещё не сохранён) и ничего не трогают, если всё на месте, либо создают недостающее. Общая безопасная логика — `utils/idempotent.js`: если канал/роль переименована администратором вручную, скрипт использует её как есть и не переименовывает обратно и не создаёт рядом дубликат с дефолтным именем; а если дубли уже случились (например, из-за гонки — см. ниже), детерминированно берёт самый старый ресурс по ID и явно предупреждает в логе, какие лишние — их можно удалить вручную. На VPS-деплое (см. ниже) они прогоняются автоматически при каждом push в `main` — руками запускать `node scripts/<файл>.js` нужно только при локальной разработке или если бот развёрнут не через `.github/workflows/deploy.yml`. `deploy.yml` держит `concurrency`-группу — два push подряд не запускают два деплоя параллельно (что само по себе могло приводить к дублям, даже при ID-идемпотентности каждого скрипта), второй ждёт завершения первого. Та же логика используется и в `security/backup.js` для `/backup restore` — бэкапы хранят ID роли/категории/канала, а не только имя, поэтому переименование после снятия бэкапа не приводит к дублю при восстановлении.

| Скрипт                          | Что делает                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| ------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `scripts/setup-roles.js`        | Создаёт роли модерации (Admin/Moderator/Beta-Moderator/Trusted и т.д.) с нужными правами — Beta-Moderator получает те же повседневные права, что и Moderator, кроме Kick/Ban.                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `scripts/setup-verification.js` | Создаёт канал верификации с кнопкой и панелью, настраивает роли "не верифицирован"/"верифицирован".                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `scripts/setup-tickets.js`      | Создаёт категорию, канал-панель и лог-канал для системы тикетов, роль поддержки Support и её испытательную версию Beta-Support, роли-специалистов по темам обращений (баги — роль «Разработчик бота», жалобы, апелляции) — у каждой свой цвет и позиция в иерархии на уровне Support, а не внизу списка, канал `#подтверждение-стажёров` для подтверждения закрытия тикетов, запрошенного Beta-Moderator/Beta-Support, а также отдельный канал `#сообщить-о-баге` (панель только с темой "bug") — видят его Support/Moderator (+beta) и сама роль «Разработчик бота», Support на новые баг-тикеты не пингуется. |
| `scripts/setup-temp-voice.js`   | Создаёт триггер-канал, панель управления и отдельно — категорию для самих временных комнат участников.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `scripts/setup-suggestions.js`  | Создаёт каналы "предложить-идею" (с кнопкой) и "предложения" (куда публикуются идеи).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `scripts/setup-rules.js`        | Публикует и закрепляет правила сервера в канале `#правила` (повторный запуск редактирует то же сообщение).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `scripts/setup-changelog.js`    | Создаёт канал `#обновления` для автоматических анонсов новой версии бота.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `scripts/setup-reputation.js`   | Создаёт канал `#рейтинг` для еженедельного топа и роль на каждый уровень репутации, включая стартовый "Новичок".                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `scripts/audit-roles.js`        | Разовый диагностический отчёт (не идемпотентный setup, ничего не создаёт и не меняет): печатает все роли сервера с их правами, позицией в иерархии и числом участников, находит задвоенные по имени роли, опасные права у `@everyone`, роли выше бота и предлагает порядок по "опасности" прав — но ничего не применяет сам. Запускать вручную: `docker compose run --rm bot node scripts/audit-roles.js`.                                                                                                                                                                                                      |

После настройки включите нужные модули (verification, antiNuke, raidShield и т.д.) через `data/security-config.json` — файл создаётся автоматически при первом запуске бота с дефолтными значениями (`security/config.js`).

## Деплой на VPS

Бот запускается на сервере через `docker compose` (см. `Dockerfile`/`docker-compose.yml`) — контейнер бота и Postgres.

### Первоначальная настройка сервера (один раз)

```bash
# Docker + Docker Compose, если ещё не установлены
curl -fsSL https://get.docker.com | sh

git clone https://github.com/extree-dev/discord-bot-new.git /root/discord-bot-new
cd /root/discord-bot-new
cp .env.example .env
nano .env   # заполнить DISCORD_TOKEN, CLIENT_ID, GUILD_ID и т.д.

docker compose up -d --build
```

### Автодеплой при пуше в main

`.github/workflows/deploy.yml` подключается по SSH к серверу при каждом push в `main`, переходит в `/root/discord-bot-new`, выполняет `git reset --hard origin/main && docker compose up -d --build`, а затем прогоняет регистрацию слэш-команд (`deploy-commands.js`) и все идемпотентные setup-скрипты из таблицы выше — так что новые команды, роли, каналы и т.п. появляются на сервере сами, без отдельного захода по SSH после каждого пуша. Для этого в репозитории (Settings → Secrets and variables → Actions) нужно задать секреты:

| Секрет        | Значение                                                                                |
| ------------- | --------------------------------------------------------------------------------------- |
| `VPS_HOST`    | IP или домен сервера                                                                    |
| `VPS_PORT`    | SSH-порт (обычно `22`)                                                                  |
| `VPS_USER`    | пользователь для SSH (например, `root`)                                                 |
| `VPS_SSH_KEY` | приватный SSH-ключ, чей публичный аналог добавлен в `~/.ssh/authorized_keys` на сервере |

`.env` на сервере деплой не трогает — секреты бота (`DISCORD_TOKEN` и т.д.) обновляются вручную на сервере, а не через GitHub Actions.

## Структура проекта

```
index.js                  — точка входа: клиент, роутинг interactionCreate, graceful shutdown
deploy-commands.js         — регистрация слэш-команд
commands/moderation/       — слэш-команды модерации
commands/general/          — общие слэш-команды
security/                  — антинюк, raid shield, automod, верификация, аудит-лог
tickets/                   — система тикетов поддержки
voice/                     — временные голосовые комнаты
suggestions/               — система предложений
presence/                  — статус бота (/status)
changelog/                 — анонсы новой версии, /changelog
reputation/                — репутация участников, /rep
commandsChannel/           — ограничение общих команд одним каналом, /commands-channel
utils/                     — общие хелперы (embeds, components, версия, безопасное хранение конфигов в Postgres)
scripts/                   — одноразовые скрипты первоначальной настройки сервера
data/                      — бэкапы структуры сервера (не в git)
```

Конфигурация каждого модуля хранится одной JSONB-строкой в таблице `bot_stores` в PostgreSQL и читается/пишется через `utils/pgStore.js` — общий примитив, который делает read-modify-write атомарным через транзакцию с `SELECT ... FOR UPDATE`, чтобы параллельные взаимодействия (например, два тикета закрываются одновременно) не теряли изменения друг друга.

## Известные ограничения
