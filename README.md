# discord-bot

Discord-бот для модерации сервера на [discord.js](https://discord.js.org/) v14: система безопасности (антинюк, raid shield, automod, верификация), тикеты поддержки и временные голосовые комнаты.

## Возможности

Общее правило видимости: ответ на любую команду или нажатие кнопки — ephemeral (виден только тому, кто её вызвал/нажал), кроме единственного явного исключения — `/level leaderboard` (топ активности виден всем в канале, это витрина, а не личный ответ). Персистентные панели (открыть тикет, статус голосовой комнаты, предложить идею, карточка левел-апа/еженедельный топ активности) — не ответы на команду, а самостоятельные публичные сообщения, их это правило не касается.

- **Общие** — `/ping`, `/help`, `/userinfo`, `/serverinfo`, `/rules`, `/version`, `/changelog`, `/level` (уровень активности).
- **Модерация** — слэш-команды `/ban`, `/kick`, `/timeout`, `/warn`, `/warnings`, `/clear`, `/unban`, `/slowmode`, `/role`, `/lockdown`, `/status` (управление статусом бота, с ротацией), `/dashboard` (сводная панель модератора), `/verification-role` (указать роли верификации напрямую, без редеплоя), `/say` (сообщение от имени бота в канал), `/dm` (личное сообщение от имени бота), `/dm-clear` (удалить сообщения бота в личке с участником), `/commands-channel` (ограничить общие команды одним каналом), `/temp-voice-category` (указать категорию для временных комнат), `/mod-queue` (проверка сообщений перед публикацией в выбранных каналах), бэкап сервера, статус системы безопасности.
- **Безопасность** (`security/`)
    - **Anti-nuke** — следит за массовым удалением каналов/ролей, банами, выдачей опасных прав и созданием подозрительных вебхуков через audit log; при превышении лимита действий за окно времени снимает роли и банит исполнителя (если он не в списке доверенных).
    - **Raid shield** — при аномальном всплеске заходов новых участников временно поднимает уровень верификации сервера.
    - **Automod** — банит массовые упоминания, спам сообщениями, ссылки-приглашения, фишинговые/скам-ссылки, избыточный капс и запрещённые слова; копит предупреждения и эскалирует до таймаута/бана.
    - **Lockdown** (`/lockdown on|off`) — ручная экстренная блокировка всех каналов сервера, состояние сохраняется в БД.
    - **Верификация** — простая captcha (кнопка + модальное окно) перед выдачей роли на сервере.
    - **Audit log** — лог действий модерации в отдельный канал; туда же пишутся `/say` и `/dm` (кто из администраторов и что отправил от имени бота — Discord сам такое не логирует).
- **Кастомный мут** (`moderation/`) — `/timeout` и кнопка «Наказать» на карточке жалобы не используют нативный Discord-таймаут (Communication Disabled Until): у него жёсткое ограничение платформы — пока он активен, участник не может нажать вообще ни одну кнопку и использовать вообще ни одну слэш-команду на сервере. Вместо этого назначается роль `Muted` с явным запретом писать/реагировать/подключаться к голосу/использовать слэш-команды почти везде на сервере (оверрайт ставится на каждый канал и категорию, не только категории — иначе его мог перебить собственный оверрайт какого-то другого канала, `scripts/setup-roles.js`; на новые категории/каналы, созданные позже, оверрайт ставится автоматически). Срок мута отслеживается отдельно (БД, не нативный Discord-таймер) и снимается автоматически по истечении. `/dashboard` показывает число активных мутов.
- **Уведомление о наказании** (`utils/punishmentNotice.js`) — бот больше не пишет участникам личные сообщения сам ни для чего (единственный канал личных сообщений теперь — `/dm`, вручную администратором), поэтому `/timeout`, `/warn` и кнопка «Наказать» на карточке жалобы вместо ЛС заводят приватный тред с наказанным участником в отдельном канале `#уведомления-о-наказаниях` и пишут туда причину; тред самоудаляется через 24 часа. Для `/ban` уведомление не отправляется — забаненный сразу теряет доступ вообще ко всем каналам/тредам гильдии, прочитать его он бы всё равно не смог.
- **Жалоба на игрока** (`tickets/`) — по прямому референсу администратора система тикетов сужена до одной формы (эскалация, приоритет, рейтинги, HTML-транскрипты, испытательный срок для стажёров, отдельные темы вроде общих вопросов/апелляций/багов по-прежнему не возвращались). Публичная кнопка «Жалоба на игрока» в канале `#открыть-тикет` → модальная форма с двумя текстовыми полями (тег/ID нарушителя, описание ситуации) → бот заводит приватный тред `ticket-<N>` в канале `#обращения-в-поддержку` (сам канал видит только staff) и добавляет туда автора жалобы участником. Тред — только информационное сообщение бота, без единой кнопки: автор не должен видеть ничего интерактивного. Все действия (claim/close/punish) — только из отдельного staff-only канала `#🛠️│управление-тикетами` (`scripts/setup-ticket-management.js`): кнопка «Активные тикеты» открывает select-меню с claim-статусом каждого тикета, выбор — карточку с кнопками «Взять в работу»/«Закрыть»/«Наказать» (мут/бан — мут доступен любому staff, бан только тем, у кого есть личное право `BanMembers`).
- **Временные голосовые комнаты** (`voice/`) — авто-создание личной комнаты при входе в триггер-канал (с подстраховкой на случай, если категория ещё не в кэше бота) в отдельной категории (по умолчанию «Активные комнаты», либо любая другая через `/temp-voice-category set`) — не там, где сам триггер-канал и панель управления, чтобы та не зарастала комнатами участников, управление (лок/скрытие, лимит, кик, блок, передача владения) только через кнопки на панели — у владельца нет `Manage Channels` и нативного статуса голосового канала Discord, чтобы обойти кнопки и поменять что-то напрямую было нельзя.
- **Предложения** (`suggestions/`) — кнопка "Предложить идею" в отдельном канале → модальная форма (заголовок + описание) → публикация в канал предложений для обсуждения командой и участниками.
- **Статус бота** (`presence/`) — `/status` задаёт фиксированный текст активности (Играет в/Смотрит/Слушает/Участвует в) с подстановкой `{members}`/`{uptime}`, либо ротацию из нескольких вариантов по таймеру.
- **Что нового** (`changelog/`) — `/changelog` показывает последние версии из `CHANGELOG.md` (все, включая патчи); при первом запуске бота на новой версии карточка с изменениями публикуется автоматически в канал `#обновления`, но только для релизов — версий вида `X.Y.0` (см. SemVer в `CHANGELOG.md`). Патч-версии (`X.Y.Z`, `Z > 0`) — багфиксы, они молча остаются только в истории.
- **Канал команд** (`commandsChannel/`) — `/commands-channel set|clear` ограничивает общие команды (не модерацию) одним каналом: вызов не в нём не выполняется, в ответ приходит ephemeral-подсказка (видно только автору) с указанием нужного канала.
- **Уровень активности** (`leveling/`) — очки начисляются автоматически за собственную активность участника, а не за "выдачу" от других: +5 за каждое засчитанное сообщение (не чаще раза в минуту с человека — иначе флуд накручивал бы уровень быстрее реальной активности) и +2 за каждую минуту в голосовом канале (кроме AFK-канала), пока участник в нём подключён — начисляется батчем раз в минуту, а не по одной транзакции на человека. Очки конвертируются в целочисленный **уровень** (300 очков = 1 уровень, растёт неограниченно), а уровень — в **ярус** (роль/титул): Новичок (0) → Путник (5) → Рекрут (15) → Боец (30) → Специалист (50) → Мастер (75) → Хранитель (100). Роли ярусов складываются — на 50 уровне участник держит все роли от Путника до Специалиста одновременно, поэтому каждый ярус несёт только свой новый бонус:
    - **Путник** — стрим и веб-камера в голосовых каналах (`Stream`).
    - **Рекрут** — вложения (картинки/файлы) и ссылки-превью в любых текстовых каналах (`AttachFiles`/`EmbedLinks`).
    - **Боец** — реакции на сообщения (`AddReactions`).
    - **Специалист** — сторонние эмодзи и стикеры (`UseExternalEmojis`/`UseExternalStickers`).
    - **Мастер** — приоритет голоса в голосовых каналах (`PrioritySpeaker`).
    - **Хранитель** — престижная роль без дополнительных прав, выделяется в списке участников.
    - Бустер сервера (нативная роль Discord) получает бонусы ярусов Путник-Специалист сразу, без прокачки.

    `/level profile` целиком одной картинкой (не embed/текстом) — баннер профиля пользователя как фон (градиент в цвет яруса, если баннера нет), круглый аватар в рамке цвета яруса, имя, титул яруса, номер уровня, полоса прогресса до следующего яруса того же цвета, строка "осталось N уровней до «Титул»"/сколько сообщений, времени в голосовых и очков всего, место в рейтинге (золото/серебро/бронза для топ-3) и уголок с иконкой/именем сервера; рисуется на сервере через `@napi-rs/canvas` (кириллица — через `@openfonts/noto-sans_cyrillic`, без системных шрифтов в контейнере). Цвет яруса — общий для роли и карточки: единственный источник — `LEVELS` в `leveling/model.js`. `/level leaderboard` — тоже картинкой, не embed'ом, тем же визуальным языком, что и `/level profile`: все места — одинаковые строки (аватар в рамке цвета яруса, титул + номер уровня, число сообщений, полоса прогресса до следующего яруса тем же цветом, счёт), топ-3 отмечены только цветом номера места — без подиума/спецэффектов; `/level set` — ручная правка счёта для модерации (выдаёт все роли ярусов вплоть до нового, а не только последнюю). Роль стартового яруса выдаётся не за очки, а сразу при верификации (стартовая "Новичок" — `security/verification.js`) и автоматически при повышении (роли создаёт `scripts/setup-leveling.js`, синхронизируя имя/цвет/права роли с кодом при каждом деплое; публикует карточку level-up в канал `#рейтинг`); раз в неделю бот сам постит туда же картинку топа с изменением позиции относительно прошлой недели (`+N`/`-N`/`=`/`новый` — цветная плашка у каждой строки). Обе картинки уровня (профиль и топ) делят общие примитивы рисования в `leveling/canvasUtils.js`.

- **Очередь модерации сообщений** (`modqueue/`) — `/mod-queue add|remove|list` включает/выключает проверку в конкретных текстовых каналах без редеплоя. В таких каналах сообщение участника сразу удаляется (текст + до 4 вложений по 8МБ каждое скачиваются в память ДО удаления, пока их CDN-ссылки ещё живы) и уходит карточкой в скрытый канал `#очередь-модерации` — видит только модерация (Admin/Moderator/Beta-Moderator/Support), обычные участники канал не видят вообще. Кнопки «Одобрить»/«Отклонить»: одобрение публикует сообщение от лица бота с именем автора жирным текстом (не пингом — публикация собственного одобренного сообщения не должна слать уведомление), отклонение просто снимает заявку с рассмотрения — карточка в обоих случаях правится на месте (`Message#edit`, как подтверждение закрытия тикета стажёром), показывая, кто её решил. Заявки на проверке хранятся в памяти процесса, не в БД — при перезапуске бота уже поданные, но нерассмотренные заявки теряются, их карточки после этого честно отвечают "заявка недоступна" вместо попытки опубликовать пустоту.

## Требования

- Node.js 18+
- Discord-приложение и бот-токен ([Discord Developer Portal](https://discord.com/developers/applications))

### Права бота и intents

При приглашении бота на сервер нужны минимум права: `Manage Roles`, `Manage Channels`, `Kick Members`, `Ban Members`, `Moderate Members`, `Manage Messages`, `View Audit Log`, `Send Messages`, `Read Message History`, `Connect`/`Move Members` (для временных голосовых комнат), `Create Private Threads`/`Manage Threads` (для приватных тредов уведомлений о наказании).

В Developer Portal → Bot включите privileged intents: **Server Members Intent** и **Message Content Intent** (используются `GatewayIntentBits.GuildMembers` и `GatewayIntentBits.MessageContent` в `index.js`).

## Установка

```bash
npm install
cp .env.example .env
```

Заполните `.env`:

| Переменная      | Обязательна | Описание                                                                                                                                              |
| --------------- | ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `DISCORD_TOKEN` | да          | Токен бота из Developer Portal.                                                                                                                       |
| `CLIENT_ID`     | да          | Application ID бота (для регистрации слэш-команд).                                                                                                    |
| `GUILD_ID`      | нет         | ID сервера для мгновенной регистрации команд на конкретном сервере (без него — глобальная регистрация, до часа на распространение).                   |
| `TRUSTED_IDS`   | нет         | ID пользователей через запятую, которым система безопасности всегда доверяет (не считает подозрительными). Владелец сервера доверенный автоматически. |

`.env` и всё содержимое `data/` (конфиги, счётчики тикетов, бэкапы) в `.gitignore` — не коммитятся.

## Запуск

```bash
npm run deploy   # зарегистрировать/обновить слэш-команды в Discord
npm start         # запустить бота
```

`npm run deploy` регистрирует команды на конкретном сервере, если задан `GUILD_ID` (и очищает глобальные — иначе одна и та же команда была бы видна дважды), иначе — глобально (до часа на распространение).

## Настройка после первого запуска

Все скрипты в `scripts/` (кроме `migrate-json-to-postgres.js`) идемпотентны: находят уже созданные роли/каналы/панели по сохранённому ID (запасной вариант — по названию, только если ID ещё не сохранён) и ничего не трогают, если всё на месте, либо создают недостающее. Общая безопасная логика — `utils/idempotent.js`: если канал/роль переименована администратором вручную, скрипт использует её как есть и не переименовывает обратно и не создаёт рядом дубликат с дефолтным именем; а если дубли уже случились (например, из-за гонки — см. ниже), детерминированно берёт самый старый ресурс по ID и явно предупреждает в логе, какие лишние — их можно удалить вручную. На VPS-деплое (см. ниже) они прогоняются автоматически при каждом push в `main` — руками запускать `node scripts/<файл>.js` нужно только при локальной разработке или если бот развёрнут не через `.github/workflows/deploy.yml`. `deploy.yml` держит `concurrency`-группу — два push подряд не запускают два деплоя параллельно (что само по себе могло приводить к дублям, даже при ID-идемпотентности каждого скрипта), второй ждёт завершения первого. Та же логика используется и в `security/backup.js` для `/backup restore` — бэкапы хранят ID роли/категории/канала, а не только имя, поэтому переименование после снятия бэкапа не приводит к дублю при восстановлении.

| Скрипт                               | Что делает                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `scripts/setup-roles.js`             | Создаёт роли модерации (Admin/Moderator/Beta-Moderator/Trusted и т.д.) с нужными правами — Beta-Moderator получает те же повседневные права, что и Moderator, кроме Kick/Ban.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `scripts/setup-verification.js`      | Создаёт канал верификации с кнопкой и панелью, настраивает роли "не верифицирован"/"верифицирован".                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `scripts/setup-tickets.js`           | Создаёт категорию, публичный канал-панель `#открыть-тикет` (только кнопка, писать нельзя) и приватный канал-родитель `#обращения-в-поддержку` для тредов жалоб (сам канал и приватные треды внутри видит только staff — роль Support получает `ManageThreads`), роль поддержки Support. Самоисцеляющаяся очистка: если на сервере остались каналы `#сообщить-о-баге`/`#баг-репорты` от прежней многотемной системы — удаляет их.                                                                                                                                                                                                                                                                        |
| `scripts/setup-ticket-management.js` | Создаёт staff-only канал `#🛠️│управление-тикетами` с панелью-сообщением (кнопки «Активные тикеты» — список неархивированных тредов жалоб, «Статистика» — открыто сейчас/всего создано/жалоб в истории). Категория задаётся один раз ID напрямую (по запросу администратора), дальше скрипт работает по уже сохранённому ID канала/категории, как и остальные `setup-*.js`.                                                                                                                                                                                                                                                                                                                              |
| `scripts/setup-temp-voice.js`        | Создаёт триггер-канал, панель управления и отдельно — категорию для самих временных комнат участников.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `scripts/setup-suggestions.js`       | Создаёт каналы "предложить-идею" (с кнопкой) и "предложения" (куда публикуются идеи).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `scripts/setup-rules.js`             | Публикует и закрепляет правила сервера в канале `#правила` (повторный запуск редактирует то же сообщение).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `scripts/setup-changelog.js`         | Создаёт канал `#обновления` для автоматических анонсов новой версии бота.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `scripts/setup-leveling.js`          | Создаёт канал `#рейтинг` для еженедельного топа активности, роль на каждый ярус (включая стартовый "Новичок") с правами по коду, выдаёт роли Booster'у бонусы 5-50 ярусов, удаляет ранее созданные клубные каналы ярусов, если они ещё остались с прошлых деплоев.                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `scripts/setup-modqueue.js`          | Создаёт скрытый канал `#очередь-модерации` (видит только модерация) для карточек на одобрение сообщений — какие каналы проверяются, задаётся отдельно командой `/mod-queue add`, скрипт этим не занимается.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `scripts/audit-roles.js`             | Разовый диагностический отчёт (не идемпотентный setup, ничего не создаёт и не меняет): печатает все роли сервера с их правами, позицией в иерархии и числом участников, находит задвоенные по имени роли, опасные права у `@everyone`, роли выше бота и предлагает порядок по "опасности" прав — но ничего не применяет сам. Запускать вручную: `docker compose run --rm bot node scripts/audit-roles.js`.                                                                                                                                                                                                                                                                                              |
| `scripts/fix-role-hierarchy.js`      | Разовая проверка+починка иерархии ролей (не входит в деплой, запускать вручную по мере надобности): те же находки, что и `audit-roles.js`, но безопасное и однозначное чинит сам — снимает опасные права с `@everyone`, возвращает роли, которые провижинит бот (Moderator/Beta-Moderator/Trusted/Muted), на канонические позиции под ролью бота, если их сдвинули вручную. Задвоенные роли и роли выше бота — только предупреждает в консоли, чинить их автоматически рискованно (нужно решение администратора). `docker compose run --rm bot node scripts/fix-role-hierarchy.js`.                                                                                                                     |
| `scripts/fix-duplicates.js`          | Разовая уборка дублей ролей/каналов/категорий по всему серверу (не входит в деплой). По умолчанию — только отчёт (dry-run); канонический ресурс — самый старый по ID (та же логика, что `pickOldest` в `utils/idempotent.js`). С флагом `--apply` реально переносит участников дублей ролей на канонический, переносит дочерние каналы дублей категорий на канонический, удаляет сами дубли, а затем правит все config-сторы фич (`changelog`/`commandsChannel`/`leveling`/`modqueue`/`presence`/`rules`/`security`/`suggestions`/`tickets`/`voice`), заменяя ссылки на удалённые ID на канонические. `docker compose run --rm bot node scripts/fix-duplicates.js` (добавь `--apply`, чтобы применить). |

После настройки включите нужные модули (verification, antiNuke, raidShield и т.д.) через `data/security-config.json` — файл создаётся автоматически при первом запуске бота с дефолтными значениями (`security/config.js`).

## Деплой на VPS

Бот запускается на сервере через `docker compose` (см. `Dockerfile`/`docker-compose.yml`) — контейнер бота и Postgres.

### Первоначальная настройка сервера (один раз)

```bash
# Docker + Docker Compose, если ещё не установлены
curl -fsSL https://get.docker.com | sh

git clone https://github.com/extree-dev/discord-bot-new.git /root/discord-bot-new
cd /root/discord-bot-new
cp .env.example .env
nano .env   # заполнить DISCORD_TOKEN, CLIENT_ID, GUILD_ID и т.д.

docker compose up -d --build
```

### Автодеплой при пуше в main

`.github/workflows/deploy.yml` подключается по SSH к серверу при каждом push в `main`, переходит в `/root/discord-bot-new`, выполняет `git reset --hard origin/main && docker compose up -d --build`, а затем прогоняет регистрацию слэш-команд (`deploy-commands.js`) и все идемпотентные setup-скрипты из таблицы выше — так что новые команды, роли, каналы и т.п. появляются на сервере сами, без отдельного захода по SSH после каждого пуша. Для этого в репозитории (Settings → Secrets and variables → Actions) нужно задать секреты:

| Секрет        | Значение                                                                                |
| ------------- | --------------------------------------------------------------------------------------- |
| `VPS_HOST`    | IP или домен сервера                                                                    |
| `VPS_PORT`    | SSH-порт (обычно `22`)                                                                  |
| `VPS_USER`    | пользователь для SSH (например, `root`)                                                 |
| `VPS_SSH_KEY` | приватный SSH-ключ, чей публичный аналог добавлен в `~/.ssh/authorized_keys` на сервере |

`.env` на сервере деплой не трогает — секреты бота (`DISCORD_TOKEN` и т.д.) обновляются вручную на сервере, а не через GitHub Actions.

## Структура проекта

```
index.js                  — точка входа: клиент, роутинг interactionCreate, graceful shutdown
deploy-commands.js         — регистрация слэш-команд
commands/moderation/       — слэш-команды модерации
commands/general/          — общие слэш-команды
security/                  — антинюк, raid shield, automod, верификация, аудит-лог
tickets/                   — форма жалобы на игрока (кнопка → модалка → приватный тред)
voice/                     — временные голосовые комнаты
suggestions/               — система предложений
presence/                  — статус бота (/status)
changelog/                 — анонсы новой версии, /changelog
leveling/                  — уровень активности участников, /level
commandsChannel/           — ограничение общих команд одним каналом, /commands-channel
modqueue/                  — очередь модерации сообщений, /mod-queue
utils/                     — общие хелперы (embeds, components, версия, безопасное хранение конфигов в Postgres)
scripts/                   — одноразовые скрипты первоначальной настройки сервера
data/                      — бэкапы структуры сервера (не в git)
```

Конфигурация каждого модуля хранится одной JSONB-строкой в таблице `bot_stores` в PostgreSQL и читается/пишется через `utils/pgStore.js` — общий примитив, который делает read-modify-write атомарным через транзакцию с `SELECT ... FOR UPDATE`, чтобы параллельные взаимодействия (например, два обращения отправляются одновременно) не теряли изменения друг друга.
